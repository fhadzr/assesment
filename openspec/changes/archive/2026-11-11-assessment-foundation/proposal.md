# Proposal

## Why

The V-TEKI assessment requires three runnable, tested, reproducible prototypes in one repository, but the repo currently has only a directory skeleton: no Python packaging, no pytest configuration, no dependency isolation between cases, no Makefile targets, and placeholder docs. Every subsequent case change will assume this foundation exists, so establishing it first prevents divergent per-case conventions and untestable code later.

## What Changes

- Establish Python project conventions for the monorepo: root packaging/workspace file, per-case package layout (`src/` + `tests/`), and isolated per-case dependencies (one virtual environment per case) so case dependencies never conflict.
- Configure pytest at the root: test discovery across all three case `tests/` directories, deterministic settings, and a minimal passing smoke test per case proving the harness works.
- Establish reproducible synthetic data conventions: every dataset under a case's data directory is generated by a seeded, checked-in generator script with a recorded seed; no hand-authored data files.
- Create Makefile targets for the repeated workflow: environment setup (per case), running all tests, running one case's tests, cleaning caches — each executable on Windows and Unix.
- Replace the placeholder README.md with reproducible setup instructions (prerequisites, setup commands, test commands, layout).
- Complete AI_DISCLOSURE.md with the disclosure structure the assessment requires.
- Formalize the evidence storage conventions already scaffolded under `evidence/` (traceability matrix columns/statuses, experiment log format, security results, cost analysis) and keep `evidence/assessment_traceability.csv` as the maintained matrix.
- Add a root `.gitignore` covering Python artifacts, virtual environments, and cached model/vector files.

Out of scope: the three prototypes themselves (fraud model, document intelligence, RAG chatbot), their APIs, their datasets, and their evaluations. This change builds only the foundation they will sit on.

## Capabilities

### New Capabilities
- `repo-foundation`: Repository layout, Python project conventions, per-case dependency isolation, and executable Makefile workflow commands.
- `test-infrastructure`: Root pytest configuration and test discovery so that `make test` runs every case's tests and `make test-case1` (etc.) runs one case's, deterministically and offline.
- `synthetic-data`: Conventions and tooling making every dataset synthetic, seeded, and reproducible from checked-in generator code.
- `evidence-management`: Storage conventions and maintenance rules for the assessment traceability matrix and evidence artifacts (experiment logs, security test results, cost analysis).

### Modified Capabilities
- (none — `openspec/specs/` is empty; this is the first change.)

## Impact

- **Code**: new root-level files (`pyproject.toml`, `pytest.ini` or equivalent, `.gitignore`, expanded `Makefile`); per-case `src/` packages and placeholder test modules; per-case `requirements.txt` files. No existing code is modified — there is none.
- **Docs**: README.md rewritten with setup/run instructions; AI_DISCLOSURE.md structured; a short conventions doc for synthetic data and evidence storage.
- **Dependencies**: Python ≥3.11 assumed; per-case dependencies pinned in each case's `requirements.txt`; root installs only tooling (pytest). FastAPI/scikit-learn/Chroma arrive with their cases, not here.
- **Assessment rubric mapping**: this change delivers the Architecture & Engineering foundation (priority 5) that all three cases (priorities 1–3) and privacy/security (priority 4) build on; the traceability matrix rows AE-01…AE-05 and the evidence conventions trace to it.
