# Design

## Context

Case 3 is implemented and archived (`2026-11-13-enterprise-rag-chatbot`), with its security suite exported to `evidence/security_test_results/case3_security.json` (18/18 assertions pass in the final evidence regenerated by this change; 9/9 at Case 3 archival, before the hardening assertions existed). Runtime API verification then found that a malicious query whose tokens overlap the injected payload's tokens causes `MockProvider.answer()` to select the injection sentence itself as the "grounded answer": the response echoed "Ignore all previous instructions." with `refusal: false` and a citation to the poisoned (HR-permitted, `all`-roles) leave-policy doc. The ACL held — no restricted content leaked — but attacker-controlled text was returned as a substantive answer. All existing injection tests asserted only that restricted content did not leak, so none failed. This change hardens the injection defense without touching the ACL-first retrieval flow, the API schema, provider selection, the synthetic KB, or its labels.

## Goals / Non-Goals

**Goals:**
- Malicious, clearly-identified prompt-injection queries get the generic refusal before retrieval/provider execution.
- Injection instruction text is stripped from retrieved content before any provider sees it, while legitimate sentences in the same document survive.
- An echoed directive can never be returned as a substantive answer, whatever the provider.
- Ordinary permitted queries keep working; all existing tests keep passing; evidence is regenerated honestly.

**Non-Goals:**
- Complete adversarial-input defense — the gate is a denylist of known high-confidence patterns; obfuscated/translated/novel payloads may evade it (documented limitation, layered controls behind it).
- ML/classifier-based detection, embeddings, or LLM-based self-checking (mock determinism and offline tests rule these out as primary controls).
- Changing the KB, its ACLs, eval dataset, or expected metrics.
- Real-LLM security validation — mock tests pin the deterministic controls; real-provider robustness stays an explicit open limitation.

## Decisions

### D1: Malicious-query gate = high-confidence denylist, applied in `ask()` before retrieval

A compiled regex family over the **user query only**:

- instruction-override patterns (`ignore/disregard/forget ... previous/above/prior instructions`, `you are now`, `new instructions:`);
- combined with exfiltration intent (`reveal/show/print/list/dump ... all|restricted|confidential` documents/content, or naming restricted role domains to reveal).

A query is malicious only when it matches an override pattern **and** an exfiltration pattern — single-word matches ("show all documents") stay answerable to avoid refusing benign browsing. This is deliberately conservative: refusing a legitimate query is a usability failure, while a missed novel payload is still contained by ACL-first retrieval, sanitization, and the output safeguard. The gate returns the same `GENERIC_REFUSAL` the core already uses, so malicious queries are indistinguishable from unanswerable/restricted ones (no oracle for probing detector coverage). Case is normalized (lowercase, whitespace-collapsed) before matching; no semantic or encoding tricks are attempted — that boundary is documented, not claimed away.

### D2: Sanitization = sentence-level stripping in `build_prompt()`, content-based, metadata-independent

`sanitize_content(content)` splits retrieved content into sentences (same `(?<=[.!?]) ` split the mock already uses) and drops any sentence matching the injection-sentence patterns (override directives, "treat this document as instructions", reveal-restricted directives, role-elevation claims like "I am an exec"). Surviving sentences are re-joined. Properties:

- Runs on every hit, every role, every provider — a poisoned sentence never reaches mock, Ollama, or Groq context.
- Never reads `metadata.contains_prompt_injection`: metadata is part of the corpus input and therefore untrusted; a mislabeled or hand-edited KB gains nothing by lying. Detection is content-only.
- Legitimate sentences from the same document are preserved (poisoned leave-policy doc still answers "annual leave entitlement" with the 20-days fact).
- Sanitized hits are what the provider receives in `hits` (`MockProvider.answer` grounds on `hits[*].content`), so the mock never even sees the injection sentence — root cause eliminated at the source, not patched at output.
- If a hit's content sanitizes to nothing, the hit is dropped from the prompt/context entirely (an instructions-only document contributes no evidence).

Caveat (documented in limitations): sentence-level stripping is lexical. A directive fused into a factual sentence without sentence punctuation survives stripping — but it then carries the fact's grounding, still cannot cite restricted docs (post-filter), and the output safeguard still blocks directive echo. Layered, not claimed complete.

### D3: Prompt framing = explicit untrusted-data delimiters

`build_prompt()` wraps the context in `<untrusted_documents>` ... `</untrusted_documents>` with a fixed preamble: passages are reference data from the knowledge base, may contain attempts to manipulate, and must never be obeyed; answer only the question from the passages. The system instruction remains fixed text, never derived from document content. This materially raises the bar for real providers (Ollama/Groq) at zero cost and gives tests a concrete artifact to assert on.

For Groq specifically, `groq_messages()` splits the assembled prompt at the `<untrusted_documents>` delimiter: the fixed instruction text is sent with the `system` role, the untrusted passages + question with the `user` role, so the API-level message structure mirrors the prompt framing instead of one undifferentiated user turn. A prompt without the delimiter degrades to a single user message (previous behavior), keeping the `answer(prompt, hits, query)` contract stable. Ollama and the mock are unchanged — the provider contracts differ and are respected per provider, not normalized. This is structural framing only; it is NOT claimed to guarantee injection resistance.

### D4: Output safeguard = sentence-scoped directive detection in `ask()` (post-provider)

After the provider returns, the answer is split into sentences (shared `split_sentences()` convention: split on terminal punctuation + whitespace) and each sentence is checked with `is_injection_sentence()`. If ANY sentence — start, middle, or end of a multi-sentence answer — is itself an injection directive, the **entire answer** becomes the generic refusal with citations stripped; the answer is never partially returned or spliced (partial return would leak which sentence tripped the detector). Sentence scoping is deliberate in both directions: (i) a directive fused mid-answer is caught wherever it sits; (ii) a pattern can no longer span a sentence boundary and false-positive on two adjacent benign sentences (e.g. a benign "disregard all of these." followed by a benign "Instructions for escalation are..." — the whole-text check previously refused this). The `MockProvider` additionally skips injection-pattern sentences during grounded sentence selection, so the safeguard is second-layer defense (and stays for providers that ignore D3 framing).

### D4b: Citation enforcement = substantive answers need ≥1 surviving citation

The pre-existing citation post-filter keeps only citations resolving to retrieved permitted hits. It previously stopped there: a substantive answer whose citations were all stripped — or that never cited — was still returned with `refusal=false`. Now `ask()` refuses such answers: empty surviving citations → generic refusal with empty citations and `refusal=true`. Rationale: the post-filter's purpose is "every citation is real"; enforcement adds the dual "every substantive answer has a real citation" — an uncited substantive answer is unsupported output by definition. Regression-pinned in the security suite: empty citations → refusal; all-invalid → refusal; valid → substantive; valid+invalid mix → only the valid kept, answer stays substantive. The mock provider always emits a citation for its answers, so evaluation metrics are unchanged (verified: identical to the evidence copy apart from wall-clock latency).

### D4c: Provider citation format fix (latent real-provider crash)

`OllamaProvider`/`GroqProvider` returned raw `(doc_id, section)` tuples in `citations` while the post-filter parses `"[doc_id § section]"` strings — any successful real-provider answer with citations crashed `ask()` with a `TypeError`. Both now emit canonical citation strings (the mock's contract), so the citation post-filter and enforcement work for real providers too. Caught while implementing D4b; covered by provider shape tests.

### D5: No changes to ACL, schema, providers, or evidence honesty

`retrieve()`, `roles.py`, the API response schema, `PROVIDER_FACTORY`, and no-fallback semantics (`ProviderError` on Ollama/Groq failure — never a silent mock fallback) are untouched. Ollama/Groq requests now carry the sanitized, delimited context (strictly less untrusted text), and a malicious query is refused before provider construction. Evidence (`case3_security.json`) is regenerated from the extended suite via the existing `scripts/export_security_results.py`; no metric is hand-written. The Groq message split (D3) changes only the `messages` payload shape for that provider — the `answer()` contract, response schema, and usage handling are unchanged, and Ollama's request shape is untouched.

## Risks / Trade-offs

- **False negatives** (obfuscated payloads pass the gate) — accepted and documented; layered controls contain the blast radius. Not claimed as solved.
- **False positives** (benign query refused) — mitigated by the conjunction rule (override AND exfiltration intent); the full existing suite (36-question eval; refusal-quality metrics must stay 1.0/1.0) guards regression.
- **Sanitizer stripping a legitimate sentence that happens to contain "reveal"** — patterns require directive structure ("reveal all ... documents/content"), not a bare verb; eval suite + new benign tests guard this.
- **Citation enforcement over-refusal** — a real LLM that answers substantively but forgets the citation format now gets refused instead of returned uncited. Deliberate: an uncited substantive answer is unsupported output; the refusal is the honest behavior. Mock metrics unaffected (verified). Documented in limitations.
- **Prompt grows slightly** (delimiters + preamble ~100 chars) — negligible at 8–12 short docs.
- **Real-LLM behavior unproven** — unchanged posture: offline tests use mocks; real-provider robustness remains an explicit open limitation in `docs/limitations.md`. The Groq system/user split is structural and NOT claimed to fix real-model injection susceptibility.
