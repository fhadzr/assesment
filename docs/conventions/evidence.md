# Evidence Conventions

Assessment evidence — anything an assessor is meant to verify — lives under `evidence/` and nowhere else. These conventions are enforced by `scripts/check_evidence_conventions.py` (`make check-evidence`).

## The four evidence locations

| Location | Contents |
| --- | --- |
| `evidence/assessment_traceability.csv` | The traceability matrix (see below) |
| `evidence/experiment_log/` | One entry per experiment/metric run: command, seed/version inputs, result |
| `evidence/security_test_results/` | Security test outputs per case |
| `evidence/cost_analysis/` | Cost estimates with their assumptions |

Case `outputs/` directories are generated (gitignored); anything referenced as evidence must be **copied into `evidence/`** so it is tracked and verifiable.

## Traceability matrix contract

`evidence/assessment_traceability.csv` has exactly ten columns, in order:

```
requirement_id, rubric_area, criterion, points, case, scenario_id,
implementation_location, test_location, evidence_artifact, verification_status
```

Status lifecycle: `pending` → `verified` or `failed`.

- **`pending`** — initial state for every row; paths may be planned and not yet exist.
- **`verified`** — every non-empty path cell in the row (implementation, test, evidence; `+`-separated for multiples) resolves to an existing file, and the referenced tests pass. The checker mechanically enforces the path-existence half.
- **`failed`** — the requirement was attempted and its verification did not hold.

Rules the checker enforces:

- **E1** — ten columns exactly, no malformed rows.
- **E2** — status ∈ {pending, verified, failed}.
- **E3** — `verified` rows' paths must exist.
- **E4** — evidence-looking files (name contains `result`/`metrics`/`experiment`/`audit` + `-`/`_`) must not live outside `evidence/` and case `outputs/`.
- **S1** — no secrets in tracked source (see [security.md](security.md)).

## Experiment log entries

Each entry in `evidence/experiment_log/` records: the exact command run, the seed and code version needed to reproduce it, and the result — generated by or verifiable from an executable script, never hand-typed. An entry whose result cannot be regenerated by its recorded command is an integrity violation.

## Running the check

```bash
make check-evidence                          # via make
python scripts/check_evidence_conventions.py       # direct
python scripts/check_evidence_conventions.py --skip-secrets  # matrix + locations only
```

Exit 0 = conventions hold; exit 1 prints violations with rule IDs.
