# Case 3 Limitations

Each limitation maps to a design decision in `openspec/changes/enterprise-rag-chatbot/design.md`.

| # | Limitation | Design decision | Honesty note |
| --- | --- | --- | --- |
| 1 | **Lexical retrieval is weak for paraphrase**: simplified TF-IDF only matches surface tokens; semantically-equivalent questions without shared words miss relevant docs. | D3 | Recall@3 measured and reported honestly; a low value would trigger an index improvement, never metric faking. |
| 2 | **Mock provider is deterministic and near-perfect on the synthetic KB** (grounded sentence selection with ≥2-token overlap), not representative of real LLMs. | D5 | Mock results labeled `mock`; the mock-vs-real gap is documented, not hidden. |
| 3 | **Role is a declared attribute, not authentication**: the API validates the role value but performs no identity verification; anyone can claim `exec`. | D4/D7, non-goals | Documented demo posture; spec wording avoids claiming authentication. |
| 4 | **Real LLM could hallucinate or follow injection despite grounding**: citation post-filter only proves a citation is inside the retrieved set, not that the whole answer is supported. | D5/D6, risks | Optional lexical-overlap signal is a heuristic; protection against memorized restricted content is explicitly NOT claimed. |
| 5 | **No embedding/semantic recall**: recall is bounded by lexical overlap. | D11 | Same as #1; measured, not fabricated. |
| 6 | **Single generic refusal for unanswerable and restricted**: the runtime cannot (and by design does not) distinguish the two, to avoid leaking whether a restricted document exists. | D5 | Evaluation labels still distinguish them at ground-truth time. |
| 7 | **Injection defense is layered but denylist-based**: a query gate (instruction-override + exfiltration conjunction), sentence-level content sanitization, a sentence-scoped output safeguard (any directive sentence in a provider answer — start, middle, or end — converts the whole answer to the generic refusal), and citation enforcement (substantive answers require ≥1 post-filter-valid citation) pin the deterministic paths — runtime verification previously showed a token-overlap path where the mock returned an injected directive as the answer, now closed and regression-tested. Obfuscated, translated, or novel payloads that evade the denylist are NOT claimed to be caught; they remain constrained by ACL-first retrieval, sanitization, the citation post-filter, and the output safeguard. | D6 + rag-injection-hardening | Denylist ≠ complete defense; residual risk documented, not hidden. Mock-provider adversarial tests are deterministic controls only — **not real-LLM security validation** (see #4). |
| 7b | **Sentence-level sanitization is lexical**: a directive fused into a factual sentence without sentence punctuation survives stripping (it then carries the fact's grounding, still cannot cite unretrieved docs, and directive echo is still blocked by the output safeguard). Sanitization also never trusts `metadata.contains_prompt_injection` — a mislabeled/hand-edited KB gains nothing by lying, at the cost of relying on pattern matching rather than the flag. | rag-injection-hardening D2 | Layered controls behind it; boundary explicit. |
| 7c | **Sentence splitting is punctuation-based**: sentences are split on `.`, `!`, `?` followed by whitespace; directives without terminal punctuation (e.g. run-on text or exotic separators) are judged as part of a longer "sentence" and only trigger the output safeguard if the pattern matches within that whole chunk. | rag-injection-hardening D2/D4 | Conservative in both directions; documented rather than solved with an NLP segmenter (would add a dependency and its own failure modes). |
| 7d | **Groq system/user message split is structural framing, not a security guarantee**: the fixed instruction text is sent as the `system` message and untrusted passages stay in the `user` message, mirroring the prompt framing at the API level. This does not guarantee the model resists prompt injection; the layered controls above remain the actual defense. Ollama and the mock are unaffected. | rag-injection-hardening D3 | Real-model robustness untested offline (mock tests only); no claim made. |
| 8 | **Windows-first**: tested on Windows 10.0.26200; POSIX assumed compatible but not CI-tested here. | foundation D7/D8 | Raw pip/pytest fallbacks in docs/README.md. |
